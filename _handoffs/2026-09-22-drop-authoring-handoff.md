## The decision, and why

The Content Packs tab was built as an **authoring tool** as well as a publisher: Drafts, Preserved
archives, an "Authoring handoff" brief, an authorship acknowledgement, four sub-tabs and a
Story-Studio-registry cross-check. But authoring never actually happened in the app — the brief
just tells you to go run an authoring session, and those sessions (the Story Studio skills + the
Story repo) build a **self-contained `.sspack`**. The owner's own 168 packs were all built that way,
entirely outside the app.

So the owner decided, 2026-09-22:

1. **Drop the authoring surface entirely** — the app publishes packs, it does not author them.
   The owner is a customer too, with a bigger toolbox outside the app.
2. **Drop the registry cross-check** — *"as long as it works, it works"*. A pack already states
   its own product identity in its manifest, so the gateway can read it instead of validating it
   against a Story Studio registry. This removes the gateway's **last dependency on a Story
   Studio source checkout**: a customer's Mac and the owner's Mac behave identically.

**Already done in the session before this one** (do not redo):

- One view for every install: no tab bar, no Preserved/Drafts, no acknowledgement; *set up once if
  needed → add a pack → see it*. Console copy simplified accordingly.
- `status()` no longer reports an `authoring` flag (it was added, then removed at the owner's
  direction); the published status contract is back to its original six keys.
- The customer import path exists and works: `import_and_publish` +
  `POST /api/content-library/import-and-publish` + the console's *Add a pack someone sent you*.
- `gateway/data/historical-identities.json` ships the historical-identity guard (baseline revision
  289, 180 pack ids, 180 family ids, no key material), regenerated by
  `store-analysis/export_historical_identities.py`.

## Target behaviour when this is finished

The gateway is **an import-only private publisher**. There is no authoring path anywhere:

- `setup()` initialises the authority from the **shipped** `historical-identities.json`. If that
  file is missing, it **fails closed** — never a silently unguarded authority.
- `publish_archive(digest)` **always** builds the release from the archive's own contents:
  - identity **read** from the manifest's `entitlement: {sku, family}` (fall back to the
    `pack.` → `sku.`/`family.` derivation only when a pack declares none),
  - item ids from the manifest's `items[].id`,
  - title / description / tags from the pack's first document,
  - **Story's twelve-tag cap applied by hand** (thirteen tags once emptied Story's whole
    catalogue; no parser runs on this path, so the trim is explicit),
  - receipt `import:<sha256>` with `receipt_revision = baseline + 1 + releases`, which must sit
    **above** the baseline or the historical-identity guard would refuse the pack it was written for,
  - the historical-identity refusal itself stays: any pack or family id in the shipped baseline is
    refused with `CONTENT_IDENTITY_HISTORICAL`.
- The Ed25519 signing path is untouched — that is what makes the shelf a publisher.

## Gotchas that will bite you (each cost real time)

- **Run test suites one file at a time.** `python -m unittest discover` cross-contaminates: every
  suite sets its own `GATEWAY_*` environment at import, so whichever loads first wins and the rest
  fail with dozens of unrelated errors. This is documented in `AGENTS.md`.
- **Never `rm` anything.** Every removal moves into `_trash/` in that project, and `_trash/` itself
  is the owner's — never delete or tidy *inside* it. Record a removed git branch's name+SHA in a
  note under `_trash/` before deleting the ref.
- **Finished work is committed, pushed, and carries a DMG in `dist/`.** Land it in `main`:
  `git -C /build/Developer/gateway-kh/repository merge --ff-only codex/content-pack-delivery`
  then `git push origin main`. Move the older DMG into `_trash/superseded-dmg/`.
- **The running app serves the gateway from inside its own bundle**, so console/Python edits are
  invisible until you rebuild and install: `sh menubar/build.sh` (installs) — and the app must be
  restarted. Promotion procedure: quit the app → **kill the gateway by PID, never `pkill -f`** →
  `ditto` the built app over `/Applications/gateway-kh.app` → `codesign --verify --deep --strict` →
  `open` → confirm `/health`.
- **Do not run `tests/test_ui.py`** — it is a release gate that takes over the owner's app. For
  native changes use a named read-only check from `tests/check_native.py` in the background.
- **Story's twelve-tag cap is load-bearing.** Thirteen tags returned a 500 for the *whole*
  catalogue. Any path that builds a product row without Story's parser must apply it.
- **The historical-identity guard's revision rule is `receipt_revision > baseline_revision`.**
  The shipped baseline is 289 and every published release sits at 290+. A receipt revision at or
  below the baseline is refused as historical — that is exactly how an emailed Store pack is kept out.
- **`_node_request` is not authoring.** It runs the signer; deleting it breaks every download grant.
- The owner keeps **FileVault off** deliberately for autologin. Do not raise it.
