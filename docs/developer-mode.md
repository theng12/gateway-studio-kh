# Run a fleet model test

The browser and Mac app share the **Run test** page. It uses the existing registered controller path; it never opens SSH, a worker connection or a general file route.

1. Filter the registered Macs by chip, physical RAM and name/node ID. The filters intersect. Select the intended Mac, such as the fleet's reported M2 Pro with 32 GiB; missing hardware facts are not inferred from its label. Changing a filter removes selected Macs it hides. The form names the exact targets before Run.
2. Read the selected Macs' capabilities and switch. Developer Mode starts Off. Turn it On only deliberately. An unsupported/unverified Hub, pause or unavailable target cannot authorize a test. Production takes priority; the Hub owns atomic admission and stopping test-owned work.
3. Choose a model, packaged fixture set, memory mode and finite settings inside the live shared bounds. Missing supported weights may be installed by the Hub; the page discloses this. There is no fixed Qwen model ID, assumed step count, RAM formula or guessed reference maximum.
4. **Run test** reads fresh inventory and checks that each selected identity, chip and RAM still agrees. It never adds newly discovered Macs. The Gateway persists the filters, inventory time, exact controller/node IDs, key and request bytes before dispatch. Unknown acceptance remains on that original controller/node/key; it never automatically retries or substitutes another Mac.
5. **Collect status / log** collects the receipt and a bounded immutable log chunk back to this Mac. The table shows collected/total bytes; repeat collection while bytes remain. Chunks resume after restart, and split UTF-8 is decoded only after the full hash verifies. A failed or incomplete collection stays a recovery hold. **Read log** shows only the fully verified retained redacted log.
6. A complete passed result enables **Review evidence**. Check its exact node, hardware, model revision, runner, settings, receipt and previous values. **Approve and publish measured limits** is a separate owner action. A pass alone publishes nothing. Stale proposals conflict and must be reviewed again.
7. **Published measured limits** reads only approved observations through the qualification reader. **Restore previous evidence** restores the previous exact scope, keeping attempts, receipts and approval history.

The frozen candidate-2 contract permits four observations: available physical/unified memory immediately before a successful start, inference time, peak sampled owned-process-tree RSS and sampled system swap growth. Runtime uses seconds; the other three use bytes. These are measured observations for that exact finite workload, not universal engine maxima. In particular, approval has no max-reference/max-prompt field and changes no Hub grant, intrinsic limit, model default or production setting. A future Hub evidence-application route requires a separate agreement.

The Gateway source flow and disposable fixture proof are not a real Qwen measurement. The normal coordinated gate/package and matching supported Hub release must complete before a real run on a verified eligible fleet node. The current batch waits behind Story 383 r5 and Hub 223.
