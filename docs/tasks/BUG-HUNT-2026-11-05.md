## Repeated pattern → shared prevention

| Pattern | Repeated root cause | Shared guard in this batch | Regression boundary |
|---|---|---|---|
| Dispatch stalls | A slot is booked before a fallible claim/thread launch, but cleanup lives only in a thread that never started | `Worker._start_job` transfers the booking or releases it and unclaims unsent work; failed hold-sweep launch clears its flag and logs why | Claim failure before/after commit, refused fresh/resume launch, next-pass progress, refused recovery-sweep launch |
| Unknown outcomes | An accepted identity or a transport error is mistaken for an outcome | `settled_failure` is used only at explicit terminal cloud poll verdicts; `_sync_recovery` gives chat/embeddings/vision the same timeout-versus-drop rule | Five deferred adapters, 15 explicit terminal states, missing-task control, failed-poll/deadline controls; dropped connection versus slow-model timeout |
| Routing/targeting | One decision is evaluated outside the existing refusal/reroute or per-job validation boundary | Changed image cells enter the existing known-not-accepted site refusal path; strict target validation occurs before per-job dispatch decisions and malformed replay conflicts | Alternate site receives the image once, refused site receives nothing; one corrupt stored target cannot block the next job or lose its restriction on replay |
| Contract drift | Catalogue, admission and routing use different meanings of zero, minimum or available permission | Shared legacy reader preserves stated zero; authoritative table updates both catalogue minimum fields; submit refusal uses the existing location-taking-work/drain predicates | Zero/false/negative distinction, submit-door zero enforcement, flat/nested minimum equality and paused/drained/retired location controls |

These guards prevent the tested mechanisms. They do not prove that no new bug can occur, reconstruct historical missing evidence or turn synthetic tests into hardware qualification.
