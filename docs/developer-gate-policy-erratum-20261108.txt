An existing persisted owner policy is never silently rewritten. Requests pin
the effective persisted policy revision and minimum_internal_physical_bytes,
not a hardcoded default. A changed policy requires a new revision and matching
request/capability policy values. Setting the minimum to0 still disables only
the capacity comparison.

Internal/physical flags, verified workspace-to-physical-device mapping,
registered identity/authentication, fresh per-run actual free-disk evidence,
idle/Production priority, exclusions and all finite resource bounds remain
required. A nominal class label or filesystem capacity is never used as a
physical-device measurement. Inventory alone never confers admission.

No deployment, supported runner, installation or remote dispatch is implied.
