# Recover a Gateway from a nightly settings backup

The secret-free nightly backup is off until the owner turns it on. It runs at the time in the existing backup settings (03:00 by default), while the Gateway is running; if the Mac was asleep, it runs after the Gateway wakes. It writes one archive in `<GATEWAY_DATA>/backups/nightly/`, keeps the newest 14, and moves older archives to the Gateway's `_trash` folder. The existing full backup is a separate feature and can contain secrets.

To turn the settings backup on, send `PUT /admin/api/settings/backup` with `{"settings_nightly": true}`. The existing `include_fleet` setting controls whether the roster is included; set it to `true` deliberately if this backup must carry the fleet roster. Both settings are off by default. `GET /admin/api/backup/nightly` reports whether the backup is enabled, `last_success`, `last_failure` (with its reason), and the latest archive's name, size in bytes and SHA-256. A null success means no success has been recorded. A failure remains visible even after a later success, so compare their times. An archive may exist even if a later step of that run failed. `GET /admin/api/backup/nightly/download` downloads the latest archive. These are admin routes; a remote caller needs the Gateway admin credential. Copy the downloaded archive to another Mac separately.

The archive contains these files when present: `providers.local.json`, `pools.json`, `provider-concurrency.local.json`, `model-limits.local.json`, `render_optin.json`, `fleet_warnings.json`, `voices_state.json`, `models_cache.json`, `retention.json`, `fleet_health.json`, and `fleet_orphans.json`. It contains `fleet.json` only when `include_fleet` is on. `manifest.json` lists files, missing sources and checksums; `SHA256SUMS` is for checking extracted files. The Gateway refuses the backup if an included JSON file has a credential-shaped field or a URL with user information, query parameters or a fragment; the failure reason names the file, not the value.

The backup does **not** contain `.env`, `credentials.json`, Telegram settings, signing identities, Content Packs, voice recordings or the voice catalogue, Hub voices, job history, generated files, or the app. Provider enablement is stored with credentials and is not restored by this archive. You must re-enter provider API keys and controller Fleet tokens in the Gateway's provider and Fleet settings, using your own saved keys or the respective provider and controller. Re-enter the Telegram bot token and chat settings from your own saved Telegram details if used. Set the Gateway API key again in the Gateway app settings or `.env`, then update clients to use it. The browser admin password is also excluded; set it again on the new Mac. Release and Content Pack signing keys are excluded: recover the original identities from your separate secure full backup; creating new identities changes what existing clients trust. This settings archive alone cannot recover published Content Pack files or voice recordings; recover those from a separate backup.

## Restore

1. Install the Gateway app on the replacement Mac and quit it and its Gateway process before restoring. Obtain the downloaded archive through your own copy method.
2. In the Gateway source or bundled Python environment, call the existing restore function with the archive's absolute path. For a source checkout with its environment installed, run this from the checkout, replacing the example path:

   ```sh
   .venv/bin/python -c 'from pathlib import Path; from gateway import backup; print(backup.restore(Path("/path/to/kh-backup-20261031-030000.tar.gz")))'
   ```

   `GATEWAY_DATA` must point to the destination Gateway data folder if it is not the default. The default is `~/Library/Application Support/gateway-kh/data`. The restore checks the manifest and file hashes before writing. It moves differing existing files to `~/Developer/_trash/kh-backup-restore-<time>/` before replacing them; files absent from the archive are left alone. A failure can stop a restore part way, and the returned `safety_copy` identifies moved files.
3. Start the Gateway. Re-enter the missing keys and passwords, recover any separately backed-up identities, packs and voices, and check the restored provider and fleet settings. The backup switch itself is not in the archive: enable it again deliberately if needed.

Alternatively, extract into a new empty folder and run `shasum -a 256 -c SHA256SUMS` from that folder; every listed file must say `OK`. With the Gateway stopped, copy the extracted `gateway/data/` files into the destination data folder. Preserve any existing files elsewhere before replacing them. The checksum command verifies the listed files; the Gateway's restore function also checks that the archive contains exactly the files listed in its manifest.
