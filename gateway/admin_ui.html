Concurrency

How much work the gateway runs at once. The pool is its total. A cloud provider's limit is what that lane will accept, so a tier that unlocks with payment is a number here rather than a code change. A Studio Hub location sizes itself from the free workers it reports, and a number here caps that: it can throttle a busy site, and can never push more work at one than the site says it has free. The two are separate tabs because they are governed by different rules. A blank box means not set, which is not the same as a limit of one.

Queue

Every job waiting right now — accepted but not yet dispatched, deferred or not — in the order the gateway will take them, with each one's position and the size of the queue it sits in. Below that, what is bounding each lane: the pool, each operation's cap, and each site's own budget as the worker last resolved it. A running job is not in this queue at all, so position 3 of 7 counts only work still waiting.

Measured

What each model has actually carried, from real jobs this gateway has run — not what its maker advertises. The largest completion that really ran is the only figure that answers "can this lane take a bigger ask", so it is shown next to the stated ceiling, which is the maker's number and says whose it is. A dash is unknown, never zero. Nothing here is a guess: a model that has never run is not listed at all.

Model pools

One name for several models, tried in order. A caller saves a single id and the gateway walks the list until one answers, so a spent free lane or a retired model costs a retry instead of the job. A member that runs out of quota is remembered and skipped until its limit resets; if every member is out, the one that comes back soonest is tried. In a pool with free and paid members, paid ones are used only when the free ones are out for the day or busy for 15 minutes; a free member that is only on a per-minute limit is waited for instead. Edits take effect at once.
